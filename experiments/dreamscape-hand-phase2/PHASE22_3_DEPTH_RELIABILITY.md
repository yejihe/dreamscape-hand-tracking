# Phase 2.2.3 · 指尖深度可靠性诊断（2026-10-25）

## 来自 vivo S30 实机截图的事实
- Phase 2.2.2 实际显示摄像头画面、21个手部关键点与粉色食指指尖，并已处理 **392** 帧，跳过 **0** 帧。
- MediaPipe 单次推理 **83ms**、结果年龄 **84ms**：此处并不能保证所有时刻延迟均为84ms。
- ARCore 相机 XYZ：(-0.19, -0.02, 0.47)m，仍然是 **手机位姿，不是手指世界坐标**。
- 粉色圆点在屏幕左侧边界，食指有部分超出当前视角，需要继续确认边缘位置变换与深度图裁剪。
- `候选场景深度：18639mm`（18.639米），附近点9/9有值。此数明显与手在手机前几十厘米的几何距离不一致。
- **9/9有效只意味着深度图像素非零，不代表测量到的是手指表面**，也可能是背景预测、运动错配或坐标系映射问题。

## 代码调整
- 保留 2.2.2 分线程异步渲染，避免阻塞预览。
- 继续显示 ARCore AUTOMATIC filtered depth 原始值（毫米）和局部有效数量，**不会悄悄把深度强行固定到0.4m**。
- 针对近手绘画实验使用 `150..2000mm` 仅作可信度初筛；超范围标记为 **不可用于指尖三维坐标**。此阈值是项目实验条件，不是 Depth API 的官方测距范围。
- 额外显示手掌相机距离的**几何粗估**：基于食指掌指关节landmark 5和小指掌指关节landmark 17的成像间距、相机fx/fy，暂假设掌宽75mm。**未使用用户实测手掌尺寸，不能作为真实手指深度**；掌心侧转会使估计不准。差距超2.2倍时显示疑似背景深度。
- 深度映射越界、5/9以下像素有效等情况标记不可用。
- 绝不因显示粗估数值就将其当成经过验证的三维指尖XYZ。

## 下一阶段验证
1. 运行 CI 和 vivo S30 实机；确保之前21点贴合与相机流畅度仍成立。
2. 用户在明亮环境下让手与手机大约相距30、50、80cm，分别报告`场景深度`和`手掌宽度粗估`是否变化。
3. 检查食指边缘裁剪时是否会读到背景，尽量把完整手掌放在画面中央。
4. 若深度读数始终18m级，则调查 depth16 对齐、raw depth confidence 与场景补全质量；**不能将这类假深度接入 FingertipProjection**。
5. 保留进一步的物理掌宽标定、姿态补偿和时间同步测试。
