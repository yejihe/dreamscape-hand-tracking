# Dreamscape Hand · Phase 2.2 指尖深度探针（独立开发分支）

## vivo S30 已通过的前一阶段实测
用户 2026-10-25 提供两张 **Phase 2.1.3** 手机截图：
- ARCore 关联图像成功处理 **63 帧 / 79 帧**，均显示 **跳过 0**。
- **手部数 1**；食指归一化图像坐标分别为 **(0.280, 0.538)** 与 **(0.393, 0.689)**，随手势/视角变化。
- ARCore 相机 XYZ 分别为 **(-0.08, 0.19, 0.43)m** 与 **(-0.17, 0.14, 0.18)m**，**不是手指三维位置**。
- 单次手部推理 **175ms / 153ms**，不足以支持低延迟空间绘画，需要后续优化。
- 相机-CPU图像时间偏移报告都约 **9.76ms**；未证明全程同一偏移或精确同步。

因此 **Phase 2.1 本机 ARCore+MediaPipe 原生集成原型已初步验证**；但图像坐标与屏幕光学对齐、时间延迟、手指深度均未验证。

## 本实验新增
- 借助 ARCore `Frame.transformCoordinates2d(IMAGE_NORMALIZED → VIEW)`，把 MediaPipe 21 点叠加到摄像头画面。**这是二维坐标标定辅助，不是三维线条。**
- 粉色大圆是 index fingertip id 8，青色骨架及绿点辅助确认关键点位置、左右和竖屏旋转。
- 检查本机 `Session.isDepthModeSupported(Config.DepthMode.AUTOMATIC)`；支持时启用 `AUTOMATIC`。
- 当前 ARCore Frame `acquireDepthImage16Bits()` 获取场景深度，通过官方 `IMAGE_NORMALIZED → TEXTURE_NORMALIZED` 映射到深度图，显示指尖附近 3×3 中位数、中心像素和有效样本数。
- 标明 **“候选场景深度 ≠ 手指物理深度”**；有可能读取的是手背、背景、孔洞填充值或时延旧深度。若 Depth API 不支持，也不假装有三维坐标。

## 手机验收试验（必做）
1. 画面仍可启动、显示清晰，`手部数1`。
2. 在手掌张开时，**粉色圆应落在食指尖**；把手机轻微旋转/移动，确认没有90°方向错位或镜像错位。若偏移，先修 image→view 标定。
3. 观察 Depth API 是 **不支持、暂不可用、还是有候选值**；若有候选值，记录：手指距离手机约30cm、50cm、80cm时的读数。默认算法在小而快速移动的指尖上可能是背景深度，需要多点/时序和物理尺测验证。
4. 原生应用运行时不要拿“候选深度”来渲染固定空间线条；必须先确认它是真实且稳定的**光轴深度**。
5. 大量采集样本之后才连接 `FingertipProjection` 世界坐标模块；进一步通过手机绕静止手指移动验证世界坐标稳定性。
